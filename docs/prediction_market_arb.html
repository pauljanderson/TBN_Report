Exhaustive cross-venue lock scan

Snapshot time (America/New_York): 2026-10-17T13:40:06.176857-04:00. Research only. This is not gold and it is not DailyRun. No orders were sent. This update explains the same snapshot and applies the published Gemini predictions fee. It does not start a new scan.

How to read this page

  1. The gain is one dollar minus both asking prices, not the gap between them. The Yes ask and the No ask are both costs. Add them. That sum is the gross cost of one pair. The amount you stand to gain or lose per paired contract, before fees, is $1 minus that sum. If the sum is $0.97, the gross gain is $0.03 per pair. If the sum is $1.01, the gross loss is $0.01 per pair. The bid-ask spread is a different idea: it is the ask minus the bid on the same contract, on one venue. The new column is “Gain per contract $”.
  2. Gross cost is for one pair. It is the dollars to buy one Yes contract and one No contract. It is not the bill for the whole size. Whole-book dollars, before fees, equal the gain per contract times the number of pairs you can lift. That count is the min size, and only when both sizes are known. The column “Gain on min size $” is that product, before fees. It is an em dash when either size is missing.
  3. Yes ask size and No ask size are not added together. Yes ask size is how many Yes contracts are offered at that Yes ask on that venue. No ask size is how many No contracts are offered at that No ask on the other venue. Min size is the smaller of the two. That is how many pairs you can buy without walking to a worse price. If one size is missing, you cannot know the pair count. Gemini’s public book is a Yes book, so the No size is often blank. This page does not invent it.
  4. A cheap mismatch is not a lock. The contract test failed on these rows, so a sum under $1 is not profit. Both bets can lose. The saved file raw/pairs_close.csv has every compared pair whose Yes ask plus No ask landed within five cents of $1, plus the strict pairs. That is 20,810 wording mismatches (8,336 of them under $1, and 2,467 exactly $1). The earlier table on this page looked empty because it only printed mismatches under $1 from the 80 rows nearest to exactly $1.00, and those 80 sat on $1.00. Below is a fresh table of 40 distinct title pairs with the strongest shared wording. “More than” and “over” the same number were treated as the same bound. What failed is a different bound (“more than” versus “or more”), a different number, a different team, a multi-outcome market, or a PredictIt contract with no payout field in the data.
  5. The contract test, and the conservative column. A strict match needed the same New York calendar date, the same bound (more-than / over the same number), the same numbers, and shared title wording (same teams / same side). Anything else is a wording mismatch. The conservative column is “Net plus Kalshi cent reserve $”. It is the documented taker fee, plus one extra cent on the Kalshi leg. Kalshi’s own schedule says a balance-rounding charge of less than one cent per order can apply. The extra cent is a cushion, not a second price from the book.
  6. About 140,000 Kalshi contracts is not 140,000 matches. Most contracts exist on only one venue, or the words do not describe the same settlement (different threshold, different game, a combo versus a single bet). This scan compared 97,302 pairs that shared a date and some wording. Only 14 passed the contract test. For those 14, the make-or-lose numbers are the gain columns: per contract, and on the min size when both sizes are known, before fees and after the fees documented below. The economic identity, when they really are the same contract: you pay the Yes ask plus the No ask now; exactly one side pays $1 at settlement; profit equals $1 minus the cost minus the fees. If they are not the same contract, both can lose, and that identity is false.
  7. Gemini’s published predictions fee is now applied to the 14 strict pairs. The fee page (dated March 12, 2026) says a taker order is one that matches immediately, and a maker order is one that rests on the book. Lifting an ask is a taker order. The formula is taker fee = taker rate × C × P × (1 − P), with taker rate 0.07, C the number of contracts, and P the price in dollars. Fees are rounded up to the next cent. There is no settlement fee. The same page says this schedule applies to contracts listed on or after March 18, 2026, and earlier listings use a previous schedule. This update did not re-fetch that previous page and does not invent a second rate. The snapshot does not store each contract’s listing date. Maker rate 0.0175 is not used here, because this scan is about buying at the ask.

Figured on one contract, the fee turns the $0.03 gap on the 2.5-point row and the 1.5-point row into a loss (fee about $0.036 and $0.037). It does not wipe the gaps on the 16.5, 18.5, 20.5, and 22.5 rows: those four still cost less than $1 after the Gemini fee plus the documented Kalshi fee, and they clear the size bar on the arithmetic. Fee assumption used

  • Kalshi. Series objects name a fee type. For quadratic and the quadratic-with-maker variants, the taker model is 0.07 times the series fee multiplier times contracts times price times (1 minus price), rounded up to the next millionth of a dollar. A taker order here means an order that buys immediately at the posted ask. The 0.07 coefficient is the one that reproduces Kalshi’s own Fee Rounding example (a $0.055 price has model fee $0.00363825). Maker fees are not added, because this scan is about lifting asks. A non-direct account can also be charged a balance-rounding fee of less than one cent per order; the conservative column adds one cent on the Kalshi leg as a cushion. flat series are “fee unknown” because the fee PDF returned HTTP 429. Combo (multivariate) markets were pulled and counted, then left out of pairing because a combo is not the same contract as a single Yes/No. On these 14 rows the saved series file gives National Basketball Association (NBA) spreads and college-football spreads a multiplier of 1 (quadratic_with_maker_fees), and the first-five-innings spread a multiplier of 0.5 (quadratic).
  • Polymarket US. Each market carries feeCoefficient. Taker fee is that coefficient times contracts times price times (1 minus price), then banker’s rounding to the cent, which is the schedule on the Polymarket US fee page (standard coefficient 0.0695). The book is one Yes instrument: the No ask used here is $1 minus the best Yes bid, and the size is that bid’s quantity. That is the reciprocal the market object already displays, confirmed on the book for pairs in the tables.
  • Polymarket international (Central Limit Order Book quotes; U.S. trading on that site is blocked, and this scan does not try to trade there). feeSchedule.rate on each market, taker only, rounded to 5 decimal places. Geopolitics-style markets with rate 0 stay at 0. If the field is missing, the row is fee unknown.
  • Gemini. Published schedule at gemini.com/fees/predictions, page date March 12, 2026. Taker fee = 0.07 × C × P × (1 − P). Maker fee = 0.0175 × C × P × (1 − P). C is the number of contracts. P is the price in dollars. Fees are rounded up to the next cent. No settlement fee and no membership fee. This scan lifts asks, so only the taker rate is applied, and only on the Gemini leg. “Fee per contract $” uses C = 1, so a raw fee of a fraction of a cent rounds up to $0.01 (or $0.02 when the raw fee is above one cent). “Gain on min size after fees $” uses C = the min size as one order, then rounds that order’s fee up to the next cent. Those two are different, because the cent rounding happens once per order, not once per contract inside a larger order. The page says this schedule covers contracts listed on or after March 18, 2026. Listings before that date use a previous schedule, which was not applied here. The public event payload shows buy-Yes and buy-No prices. The public /v1/book feed is a Yes book, so Yes size can be filled for pairs we show; No size is not invented from the Yes bid.
  • PredictIt. Fee unknown in this pull (the fee page did not return readable text, and the JSON has no fee field). The payload also has no payout field. Prices sit between 0 and 1, but PredictIt is not treated as a confirmed $1 binary here, so a PredictIt pair cannot be a lock. There is no size field.
  • ForecastEx / CME. CME is the Chicago Mercantile Exchange. No public unauthenticated JSON price board was found. Attempts are in raw/forecastex_attempts.json. Robinhood and Coinbase were not scraped; they do not publish a separate book.

A lock in the headline count needs a strict contract match on the same settlement, gross cost under $1, a documented fee on both legs, net cost under $1, and the size bar. Size must be known on both asks. The size you can lift is the smaller of the two. A one-contract stub fails the bar. A row the automated test marked strict is still not a lock when the two titles name different opponents.
