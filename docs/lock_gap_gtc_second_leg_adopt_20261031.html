Lock gap — adopted live policy: second-leg GTC (31 Oct 2026)

Adopted live policy (Paul 2026-10-31). Not gold. Not DailyRun. Written America/New_York. This replaces the immediate flatten-first one-leg rule for the second / easy leg after a hard IOC fill.

Live policy

  1. Hard / first leg: IOC (keep trading-PC thin-first / hard-first ordering).
  2. If hard fills → easy / second leg: GTC at original L (take now + rest). No post-hard REST delay required before the GTC send. Do not IOC-then-repost.
  3. If still open after 180s:
    • held ≤ 0.25 → cancel GTC, then exit (same-shop flatten if tighter, else market sell). Do not hold cheap dogs.
    • held > 25¢ → cancel GTC, then one IOC to complete at ≤ break-even (+1¢ slip); else hold to settlement.
  4. Cancel-on-resolve for resting second-leg GTCs.

Wired in this repo

tools/live_lock_orders.py: GTC TIF builders (Polymarket GTC uses synchronousExecution=false), _send_pair hard IOC → easy GTC with no forced delay, tick_one_leg_gtc_watches (cancel then send flatten / market-sell / BE-complete when orders on), cancel_second_leg_gtc_on_resolve, pure policy helpers. tools/live_game_pollers.py ticks watches after lock sends and cancels on closed results. Tests: python tools/test_live_lock_orders.py.

Enable orders (trading PC only)

Default in bare clones / cloud VMs: off. Do not flip a hard-coded True in git.

  1. Preferred: create stamp drive/paul_experiments/prediction_market_arb_exhaustive_20261017/raw/orders_enabled.on (delete / avoid orders_enabled.off, which always wins).
  2. Or set env LOCK_ORDERS_ENABLED=1 for the lock job process.
  3. Then restart the lock job (see merge_lock_gap_gtc_live.bat).

Gate function: orders_enabled(). Module flag ORDERS_ENABLED remains False by default.
