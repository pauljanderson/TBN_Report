Trading System Setup Process

End-to-end path from theory → sheet ground truth → TBN engine → seed ToS validation → post-run analysis → optimizer → ToS per lever → trade-diff → universe promotion. Shareable documentation for product-owner iteration.

TBN = Twin Beacon Networks (shared multi-system engine: stock_analysis/rocket_tbn.py). BRT = Break and ReTest — one system on that engine (output prefix BRT_). See docs/TBN_VS_BRT.md.

Setup & validation process

Theory→ Sheet (optional)→ Engine→ Seed ToS→ Post-run→ Seed opt→ ToS / lever→ Trade-diff→ Universe→ Filter→ Re-run→ Re-opt→ DailyRun
1

Come up with a theory of the system

Define the edge, regime, and entry/exit thesis before touching code. Keep it short enough that a reviewer can reject a bad fit before implementation.

Do

  • State the edge in one paragraph (what pays, why). Not “buy dips”—specify structure, filters, and expected holding period.
  • Name the market regime (and when the system should be idle). Example RL: stacked SMAs + dip into band; idle when stack broken / too extended.
  • Write entry and exit thesis (stop / target / trail / time). Map later to concrete -v levers (see ROCKET_LAUNCHER_LEVERS.md for RL; other systems: bat comments + Audit Report columns).
  • List candidate stock types (seed intuition). Leaders with history deep enough for FIRST_DATA_DATE / trade-rate math.
2

Program it in a sheet (ground truth) (optional)

Optional. Sheet / MarkTen programming is not required—you can go theory → TBN engine (step 3) directly if desired. When used, the sheet is a useful ground-truth ledger for entries, exits, and OHLC overrides before engine work.

Google Sheets / MarkTen can serve as the ledger of truth for entries, exits, and OHLC overrides. Prefer clarifying sheet behavior on the seed set when you do use this step.

Example of how a system is programmed in-sheet (MarkTen / Google Sheets): MarkTen system sheet (example).

Do

  • Build a sheet tab with In/Out, stop, target, and sizing aligned to sheet invest (~$45k). Summary later scales engine PnL via SHEET_PNL = TOTAL_PNL × (45_000 / brt_cash).
  • Load seed symbols that fit the system (e.g. MarkTen for RL / WPBR). WPBR production MarkTen list lives in run_wpbr.bat WPBR_SYMBOLS.
  • Override known bad OHLC days (combined multi-ticker formula if needed). See drive/brt_sheet_reconcile/OHLC_override_formula.md—merge tickers; never drop prior overrides.
  • Manual spot-check: 3–5 trades match chart intuition. If sheet trades look wrong, do not “fix” in Python yet.
3

Program into the TBN engine

Implement via the shared TBN host stock_analysis/rocket_tbn.py (legacy shim: rocket_brt.py) using -v mode flags that select a system (BRT, WPBR, YH, RL, RS, IND, …). Helpers live in rocket_rl.py, rocket_rs.py, rocket_MTS.py. Prefer -v levers over hard-coding. RL also has AWK in portfolio_audit.awk.

Do

  • Set the correct mode flag; isolate competing systems. RL example from run_rl.bat: rl_mode=true, brt_zones=false, yh_zones=false, indicator_buy=off.
  • Document levers consistently with Audit columns. RL lever catalog: ROCKET_LAUNCHER_LEVERS.md (intent) + ordered fields in brt_audit_columns.py / defaults in rocket_rl_config.py.
  • Confirm seed run produces Closed / Open / Report / Summary under drive/. Prefixes: BRT_, WPBR_, YH_, MTS_, RL_, RS_ + 12-digit stamp.
  • If a MarkTen / Google sheet exists for the system: reconcile engine results to the sheet (sheet is ground truth). Required for BRT, WPBR, RL, and YH when a sheet is in use. Match dates, entry prices, exit types, and PnL on the seed set before seed ToS validation (step 4), post-run, or optimizer work. WPBR: MarkTen parity tools under tools/run_wpbr_*_markten.py. RL / BRT / YH: compare Closed rows to the sheet ledger; do not treat engine CSV as correct until parity holds.
  • If RL: compare AWK and Python stamps. run_rl_compare.bat after dual run; DailyRun fails if parity breaks.
4

Produce ToS Studies for the seed set — validate these are the right trades

Parity (step 3) proves sheet ↔ engine match. This step proves the trades make sense on the chart: Closed / BO / RT / zones look like the system you intended. Qualitative gate before ImproveHints or optimizer work—do not start optimizing until seed ToS validation passes (or known exceptions are documented).

Two ToS gates: Seed ToS (this step) = pre-optimize visual check that baseline trades are right. Later ToS (steps 7–8) = accept each optimization lever / A-B trade-diff on the chart.

Do

  • Generate Thinkorswim studies for the seed / MarkTen stamp. RL: tos/gen_rl_closed_studies.py → drive/paul_studies/rl_closed_<stamp>. Other systems: same generators under tos/ or the system’s closed-study equivalent. Output under drive/paul_studies/.
  • Load studies on charts for every seed symbol that traded (and spot-check non-traders if surprising). Confirm Closed In/Out markers, stops, and (where applicable) BO / RT / zone overlays match visual expectation—not only CSV row counts.
  • Chart-validate that entries/exits fit the theory from step 1. Wrong structure on the chart = fix theory, sheet, or engine before post-run. Parity alone is not enough if both sheet and engine encode a bad trade.
  • Pass / document exceptions before moving on. Known bad OHLC days, intentional skips, or deferred symbols go in drive/paul_experiments/ notes next to the stamp. Do not proceed to ImproveHints (step 5) or seed optimize (step 6) until this gate is green or exceptions are explicit.
5

Post-run analysis — find what to improve

After seed ToS confirms trades are visually right, diagnose the seed stamp before optimizer sweeps: which symbols fit poorly, which levers to tweak, and whether a new variable is warranted. Cheap FIT / ImproveHints emit after every engine write; deep charts + HTML are manual (not DailyRun). See docs/POST_RUN_ANALYSIS.md.

CLI · post_run_analysis.py RL wrapper · rl_post_run_analysis.py ImproveHints / SymbolAssessments / ImprovePriority FIT_SCORE_ROBUST

Do

  • Run deep post-run on the seed stamp (charts on by default). Any system: python stock_analysis/post_run_analysis.py --system RL --stamp <ts> --charts (or --system BRT / WPBR / YH / …). RL shortcut: python stock_analysis/rl_post_run_analysis.py --stamp <ts> --charts. Auto-detect via drive/{PREFIX}_Closed_{stamp}.csv or pass --closed.
  • Read cheap artifacts already on Summary / ImproveHints. Summary: FIT, FIT_SCORE, FIT_SCORE_ROBUST, MAX_WIN_PCT, MEDIAN_PNL_PCT, OUTLIER_PCT_OF_WINS, FIT_ASSESSMENT. Hints: {prefix}_ImproveHints_<ts>.csv + .md. Use headline FIT_SCORE for continuity; use FIT_SCORE_ROBUST (median PnL% + outlier penalty) when deciding what to change.
  • Open deep HTML and decide: tweak an existing lever vs introduce a new variable. Outputs under drive/: {prefix}_SymbolAssessments_<ts>.html, {prefix}_ImprovePriority_<ts>.html, {prefix}_Charts_<ts>/. Prefer one coherent hypothesis for the next optimizer arm.
  • Optional (RL only): scan near-misses / blind spots. --missed-moves → RL_MissedMoves_<ts>.csv + SymbolAssessments §6 / ImprovePriority “Why we miss winners”. Heuristic — confirm on charts before changing production gates.
  • Freeze the improvement target before seeding the optimizer. Document the chosen lever or new-variable idea next to the stamp in drive/paul_experiments/. Step 6 then optimizes that target on the seed set.
6

Run selected stocks through the optimizer

Balance variables on the seed set only—guided by post-run ImprovePriority / FIT gaps (and only after seed ToS validation in step 4). Do not expand the universe until seed behavior is understood and charted.

Do

  • Choose the optimizer for the system. RL: RL_Optimizer.py (default universe data/rl_gold_universe.txt). BRT/IND-family: BRT_Optimizer.py / IND_Optimizer.py / RocketOptimizer.py. Per-symbol: run_per_symbol_optimizer.bat → Per_Symbol_Optimized_Settings_*.json.
  • Change one variable (or one coherent arm) at a time where possible. Keeps ToS and trade-diff interpretable in steps 7–8.
  • Record best settings (JSON / bat freeze / experiment folder under drive/paul_experiments/). Do not silently edit production bats during exploration; document suggested -v overrides.
  • Review hard gates (min trades, max DD, score model). RL optimizer: score mix (PnL, DD, PF, expectancy, …) + min-trades / Max_DD gates.
7

For each variable change: Thinkorswim studies

After each optimizer lever change, charts must show what the system needs: SMAs, bands, stops, In/Out markers. This is the post-optimize ToS gate (accept the lever)—distinct from seed ToS validation in step 4 (baseline trades are right before you optimize). Output studies under drive/paul_studies/.

Do

  • Generate a closed-trade study for the stamp. RL: tos/gen_rl_closed_studies.py → e.g. drive/paul_studies/rl_closed_<stamp>. Plots SMA20/50/100/200, dip band, SMA50Exp, In/Out, stop segments.
  • Load the study on charts for every seed symbol that traded. Confirm entries sit in the intended band / zone; stops match Closed ORIGINAL STOP.
  • Make the variable change visible on the chart (not only in CSV metrics). If you cannot see the lever’s effect, the experiment is incomplete.
  • Save study path + notes next to the experiment folder. Pair with HTML under drive/paul_experiments/.
8

Comparing two variables: trade-diff HTML + ToS

When comparing arm A vs arm B (two stamps / two lever values), produce a sortable trade-diff report and dual-band ToS studies showing shared vs new trades.

HTML · drive/paul_experiments/rl_stamp_trade_diff_*.html ToS · tos/gen_rl_trade_diff_studies.py ToS out · drive/paul_studies/rl_trade_diff_*

Do

  • Write trade-diff HTML (exact + close matches, new-only, metrics side-by-side). Pattern: rl_stamp_trade_diff_too_high_113129_vs_113132.html. Tables use sortable headers (project rule).
  • Generate ToS trade-diff study for symbols that differ. tos/gen_rl_trade_diff_studies.py: grey = shared/close-match; green = new-only; dual dip bands when comparing e.g. 2.4% vs 4.1%.
  • Ensure a reviewer can explain every new trade from the chart. If new trades are opaque, freeze promotion.
  • Keep only one primary lever different between stamps; document shared settings. Report/Audit columns should confirm the A/B isolation.
9

After optimizing the seed set → full universe run

Freeze seed-winning settings; run the production (or candidate) universe. Prefer the system’s bat so DailyRun parity stays intact.

Do

  • Source the universe list from bat / gold file (not an ad-hoc paste). RL: RL_SYMBOLS in run_rl.bat ↔ data/rl_gold_universe.txt. Override via env for one-offs.
  • Complete the full run; stamp Summary + Closed + Report under drive/. Copy latest via run_copy_latest.bat / DailyRun step 10 when appropriate.
  • Apply per-symbol settings if used in production. Per_Symbol_Optimized_Settings_Approved_Latest.json (RL bat default).
  • Sanity-check Report totals vs Summary rollup; no empty Closed on liquid names. Investigate zero-trade liquid names before promotion filtering.
10

Summary filters for promotion candidates

Filter *_Summary_<stamp>.csv (columns from write_brt_summary / RL mirror). Defaults below are product-owner starting points—document overrides when criteria evolve.

Promotion criteria — click headers to sort
Criterion Summary column Default threshold Notes
Trade frequency AVG_TRADES_PER_YEAR ≥ ~0.36 Minimum activity: choose stocks that trade on average at least ~0.36×/year over the study window. Years = (end − start) / 365.25; start = max(FIRST_DATA_DATE, -v start_date); end = backtest end or last OHLC / last close.
Sheet-scaled PnL SHEET_PNL > 10,000 Sheet invest $45k vs engine brt_cash (~47.5k typical). Do not compare raw TOTAL_PNL to sheet dollars without scaling.
Win rate PCT_WINS ≥ 50% WINS / TRADES × 100 (BE in denominator). Same definition as Report/Audit Pct_Wins.
No outlier-driven avg TOTAL_PNL / Closed rows Qualitative fail Reject if a single mega-winner carries the average; check P90 day distortion, top-1 trade % of total PnL, and MAE clusters. Sort Closed by PnL $; if top trade ≫ rest, demote.
History depth (context) FIRST_DATA_DATE — Not a hard gate by itself; explains short windows and inflated trade rates. In-sample “went public” proxy from symbol CSV—not an IPO API.
Spotting outliers that inflate averages: (1) One trade > ~40–50% of symbol TOTAL_PNL; (2) Removing top winner flips SHEET_PNL or PCT_WINS below threshold; (3) Avg PnL ≫ median / P90 hold days extreme vs peers; (4) Tiny TRADES with huge $ — prefer frequency filter first, then inspect Closed.

Do

  • Filter Summary with the thresholds above (or documented overrides). Keep a CSV / sheet of pass/fail with stamp ID.
  • Outlier-review every high-SHEET_PNL name. Especially low trade-count winners.
  • Write the promotion candidate list (symbols only) for step 11. Record stamp / frozen settings alongside the list in the experiment notes.
11

Re-run engine on just those stocks

Evaluate the filtered set in isolation (cleaner metrics, faster ToS, clearer drawdown).

Do

  • Re-run the engine with -s / *_SYMBOLS= limited to the promotion list. Same frozen -v levers as the universe run that produced Summary.
  • Review portfolio-level metrics (Ann ROR, Max DD, PF, expectancy). Drawdown tools: DrawdownCalc.py for RL/BRT/MTS Closed stamps.
  • Check for silent regressions vs seed behavior on overlapping names. If a MarkTen name suddenly looks different, stop and reconcile.
  • Record the decision: promote / hold / reject. Hold = needs re-opt (step 12) or more history.
12

Re-optimize on the larger set

Once the candidate universe is trusted, re-balance variables on that larger set. Every variable change again gets ToS + (when A/B) trade-diff (same post-lever gate as steps 7–8—not a substitute for the seed ToS pass in step 4).

Do

  • Re-run the optimizer with the promotion universe as default input. Update gold list / experiment config; avoid contaminating production bat until approved.
  • For each accepted lever change: regenerate ToS closed studies. tos/gen_rl_closed_studies.py (or system equivalent) on the new stamp.
  • For each A/B lever test: trade-diff HTML + trade-diff ToS. Same pattern as step 8; archive under drive/paul_experiments/ and drive/paul_studies/.
  • Validate charts on every variable change (no “CSV-only” accepts). Promotion to DailyRun / approved JSON only after visual + parity checks.
  • If RL: confirm AWK↔Python parity is still green after lever freeze. DailyRun steps 3a–3c must remain clean.
  • Production handoff: update bat flags / approved per-symbol JSON / experiment README. Document why each lever won; link trade-diff HTML.
